## 本机安装和真实运行

本机已经在项目内安装 opam 2.6.1、OCaml 5.4.1、Dune 3.24.2、Sedlex 3.7、Yojson 3.0.0 和 Menhir 20260209。没有修改系统 PATH、启用 WSL 或要求重启电脑。

Windows 后续重新构建：在项目目录运行 `powershell -File scripts/setup-nicegeo.ps1`。该脚本复用已安装环境；新机器需要先按 README 安装网站依赖。网络下载和首次编译需要时间。

实际调用为独立进程执行官方 `vendor/nicegeo/_build/default/bin/main.exe <临时证明文件>`，工作目录固定为官方源码目录，加载其 `synthetic/env.ncg`。已实际运行官方 `euclib/euclib.ncg`，返回 `Valid proofs!`，退出码0。

## 形式化步骤

网站选择前提和关系，适配层生成包含点、非退化要求、所有被选择前提和目标的封闭定理。用户只填写定理内部的 tactics，不接受新公理、外部文件导入、`sorry`、`Admitted` 或无界 `repeat`。每次请求写入独立临时目录，最长15秒，完成后清理。

当前8类关系均已通过真实 CLI 类型检查：线段等长、内角相等、严格内部点、中点、共线、点在圆上、垂直和平行。点在圆上的编码保留非零半径；角相等保留非零边要求。中点在模型允许退化时显式包含三点重合的分支，不将其误当作严格内部点。

垂直编码使用两条支持直线上的交点与直角射线，覆盖交点并非输入端点的情形。平行编码包含重合直线及严格不相交两种情况，与原有坐标约束保持一致。交换线段端点或两条线不改变关系。

普通界面选择整条线段或整个角，再选择六种常用理由之一：已知、同一个量、等式对称、线段换向、中点定义、垂直/平行换向。每个理由生成真实证明项，再调用官方检查器，不预设成功结果。

高级模式保留原有按点名精确输入及 NiceGeo 代码；高级代码留空时保留原先的基础尝试行为。例如目标 `AB=BA` 可使用 `exact (length_symm A B).`。前提名称在高级模式显示为 `h0`、`h1` 等。数学结论由网站另外展示的 Z3 约束分析独立核验；NiceGeo 只评价所提交证明，不承担任意题目的自动搜索。

测试覆盖真实自反证明、长度对称性、错误证明、8种关系的解析与类型检查、垂直/平行对称、多步垂直推理、重合直线构造、退化中点、角的非零边、常用理由生成、不允许的跳过证明及独立 Z3 结果。原始 NCG 输入与 CLI 输出可以在步骤结果中展开查看。

## 发现的运行问题

- Windows 沙盒内首次 Cygwin 安装失败；使用已授权的原生工具安装后成功。
- Windows 第一次并行编译遇到目录占用；开发服务排除工具链目录监听，编译器改为单任务安装后成功。
- `opam exec` 未自动提供 GCC 路径；构建时显式加入项目内 Cygwin 的 `bin`，没有改系统环境。
- 上游 `try reflexivity` 对非等式目标可能抛出运行异常。因此自动基础检查先匹配直接前提，只对等式尝试自反性。运行异常显示无法判断，不当成证明被否定。

## 公网部署

`Dockerfile.api` 使用固定摘要的官方 OCaml 构建镜像，编译相同提交，运行阶段仅复制官方检查器、基础环境和许可文件。Python 服务以普通用户运行；不会把 Windows 工具链、编译缓存或 IDE 打进运行镜像。Linux 每个 NiceGeo 作业另设内存、CPU 和文件大小限制。

公网前端仍调用同源 `/api/check-step`，服务器代理到 Python 服务。NiceGeo 无需安装到学生电脑。计算服务地址和 `GEOMETRY_SERVICE_KEY` 放在部署平台的服务器环境变量中。

本机没有 Docker/WSL，因此 Linux 镜像尚未实际构建运行。Windows CLI 和适配测试的成功不代表 Docker 已验证，部署前必须在 Linux/Docker 环境执行构建和同一组接口测试。
